## Tujuan belajar

Terapkan klasifikasi transaksi dan aturan dimension yang dapat dibuktikan di ledger. Semua perubahan operasional contoh dilakukan sendiri oleh pembelajar pada CRONUS sandbox.

## Konsep singkat

Dimension menjawab “transaksi milik departemen/proyek mana” tanpa memperbanyak akun. Dua global dimensions dapat dipakai pada filter utama; shortcut dimensions memudahkan input. Default dimension membantu pengisian, tetapi aturan Value Posting menentukan kewajiban/kecocokan. Dimension Combinations membatasi pasangan value, sedangkan Analysis Views mendukung analisis hasil.

## Langkah di BC

1. Di salinan CRONUS, tinjau Dimensions dan Dimension Values. Gunakan Department dan Project demo; jangan mengganti global dimensions company yang sudah aktif hanya untuk latihan.
2. Pada akun/master data latihan, isi Default Dimensions. Bedakan default value dengan aturan Code Mandatory atau Same Code sesuai kebutuhan skenario.
3. Tinjau Dimension Combinations untuk dua value demo. Catat kombinasi yang diizinkan dan yang diblokir.
4. Buat jurnal/draft transaksi tanpa dimension wajib lalu Preview. Catat error, isi value yang benar dan ulangi.
5. Setelah posting demo yang ditinjau, periksa dimension pada entries serta jumlah menggunakan filter yang sama.
6. Buka Analysis Views yang relevan, periksa konfigurasi dan kebutuhan update-nya. Bandingkan hasil dengan ledger, bukan hanya label di card.

## Contoh praktik

- **Kondisi awal** — Akun biaya demo mewajibkan Department.
- **Langkah** — Preview jurnal tanpa Department, lalu isi nilai Department yang valid dan ulangi.
- **Hasil yang diharapkan** — Kasus pertama ditolak sesuai setup. Pada kasus kedua, dimensi yang benar terlihat pada hasil preview.

## Cheat box

<CheatBox>

<CheatGroup label="Kode dan nilai">

- **Dimension code** berbeda dari value.
- Dua **global dimensions**; sampai delapan shortcut.

</CheatGroup>

<CheatGroup label="Aturan posting">

- Default tidak selalu berarti wajib.
- **Value Posting** menentukan aturan akun.

</CheatGroup>

<CheatGroup label="Validasi entry">

- **Combination** membatasi pasangan.
- Verifikasi hasil pada entry terposting.

</CheatGroup>

</CheatBox>

## Kesalahan umum

:::danger[Kesalahan umum]
Mengubah master data lalu berharap entry lama otomatis berubah, mencampur filter dimension ketika rekonsiliasi, atau menganggap semua shortcut dimension adalah global dimension.
:::
