## Tujuan belajar

Susun test script dan hasil yang dapat dipertanggungjawabkan oleh user bisnis.

## Konsep singkat

UAT memvalidasi proses dari sudut pandang bisnis, bukan menggantikan unit/functional testing. Test scenario adalah alur yang dinilai; test script memuat prasyarat, actor, data, langkah dan expected result. Actual result serta bukti diisi saat eksekusi. Status Belum dijalankan, Blocked, Pass dan Fail tidak boleh dipertukarkan.

## Langkah di BC

1. Pilih lima skenario dari matriks kebutuhan. Hubungkan ID kebutuhan, process step, role dan acceptance ke tiap skenario.
2. Siapkan company sandbox, user uji, versi/config baseline dan data demo. Pastikan functional testing cukup stabil sebelum user menjalankan UAT.
3. Tuliskan langkah bernomor dan expected result yang dapat diamati pada dokumen/ledger/approval. Jangan menggunakan hasil “berhasil” tanpa ukuran.
4. Saat praktik, isi actual result, waktu, executor, evidence dan status. Jika tidak ada akses/config, gunakan Blocked dengan alasan; jangan menulis Pass.
5. Laporkan defect berisi langkah reproduksi, expected/actual, severity, owner dan bukti. Bedakan defect terhadap spesifikasi dari kebutuhan baru yang harus masuk change request.
6. Setelah perbaikan, lakukan retest/regression yang relevan. Sign-off memerlukan coverage, defect terbuka, risiko dan keputusan process owner; persentase lulus saja belum cukup.

## Contoh praktik

- **Kondisi awal** — Uji penerimaan parsial dua dari lima belum dijalankan.
- **Langkah** — Isi langkah dan expected result. Catat actual dan bukti hanya saat kamu menjalankannya di sandbox.
- **Hasil yang diharapkan** — Script dapat direproduksi dan status awal tetap Belum dijalankan sampai ada bukti.

## Cheat box

<CheatBox>

<CheatGroup label="Rencana uji">

- Trace ke **kebutuhan** dan proses.
- Tentukan prasyarat dan data.

</CheatGroup>

<CheatGroup label="Hasil dan bukti">

- **Expected** berbeda dari actual.
- **Pass** memerlukan bukti.

</CheatGroup>

<CheatGroup label="Status dan sign-off">

- **Blocked** bukan Pass.
- Owner menyetujui risiko dan sign-off.

</CheatGroup>

</CheatBox>

## Kesalahan umum

:::danger[Kesalahan umum]
Mengisi actual result sebelum praktik, menjadikan tester sebagai approver bisnis tanpa mandat, atau menutup defect tanpa retest.
:::
