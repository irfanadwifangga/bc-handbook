## Tujuan belajar

Hubungkan BRD, kontrak API, pengujian offline dan bukti sandbox.

## Konsep singkat

Contoh repo adalah client sinkron kecil dengan HTTPX dan timeout eksplisit. Import modul tidak melakukan request. Unit test memakai MockTransport dan data sintetis; ini memeriksa perilaku client, bukan kompatibilitas end-to-end BC. Capstone utama tetap Spreadsheet-to-BC (BA/API); capstone AL adalah fase lain.

## Langkah di BC

1. Baca README di examples/api. Jalankan perintah tes offline di bawah dengan uv; tidak memakai file .env atau akun BC.
2. Pelajari test paging, nextLink asing, retry GET 429, timeout POST, konflik ETag dan deep insert. Pertahankan test yang mencegah write otomatis berulang.
3. Untuk E4/E5, pemilik menyediakan environment kredensial melalui mekanisme aman. Pilih company demo; cek sandbox secara manual sebelum memanggil fungsi write.
4. Untuk capstone CSV, tentukan mapping external key → endpoint/field, validasi seluruh baris dulu, lalu jalankan mode dry-run. Simpan rejects tanpa secret dan tinjau bersama owner.
5. Bangun importer per entity Customer/Vendor/Item di workspace latihan sendiri. Catat checkpoint setelah sukses; pada kegagalan write jangan replay batch buta. Client ini tidak menyediakan importer/journal lengkap.
6. Lengkapi bukti BRD, gap-fit, konfigurasi, impor dan UAT. Status capstone tetap Belum dijalankan sampai pemilik menguji di sandbox.

```sh
uv run --no-project --with httpx==0.28.1 python -m unittest discover -s examples/api -p "test_*.py" -v
```

`httpx` dipakai terisolasi oleh uv; tidak ditambahkan ke dependensi situs. Client tidak menyimpan token cache, tidak memperbarui token otomatis, tidak memiliki retry write otomatis, dan tidak memposting invoice. Renewal token serta journal produksi memerlukan rancangan terpisah.

## Contoh praktik

- **Kondisi awal** — CSV demo memuat dua baris dengan external key yang sama.
- **Langkah** — Siapkan dry-run untuk memisahkan baris valid dan duplikat. Tinjau payload sebelum mencoba import sandbox.
- **Hasil yang diharapkan** — Daftar penolakan menunjukkan duplikat dan dry-run tidak melakukan write.

- **Checkpoint** setelah sukses.

## Kesalahan umum

:::danger[Kesalahan umum]
Mengklaim client siap produksi karena unit test hijau, melewati data validation, atau menganggap dry-run sama dengan import sukses.
:::
