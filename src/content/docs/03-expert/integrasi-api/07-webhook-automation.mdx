## Tujuan belajar

Pilih strategi sinkronisasi dan kelola lifecycle integrasi.

## Konsep singkat

Polling membaca perubahan menurut interval; webhook memberi pemberitahuan perubahan resource. Notification adalah pemicu pembacaan, bukan bukti seluruh proses bisnis selesai. Rancang consumer yang tahan duplikasi dan urutan berbeda; rekonsiliasi berkala tetap diperlukan. Automation API mempunyai scope dan permission berbeda untuk pekerjaan setup.

## Langkah di BC

1. Tentukan SLA, volume, kebutuhan deletions dan biaya operasional. Untuk pilot kecil, mulai polling terukur dengan checkpoint dan rekonsiliasi.
2. Untuk webhook, sediakan endpoint HTTPS milik sendiri yang menangani handshake validationToken dan mengembalikannya sesuai dokumentasi. Jangan memakai URL pihak lain.
3. Daftarkan subscription hanya untuk resource yang didukung. Catat subscription ID, expirationDateTime, clientState dan jadwal renew; rahasiakan clientState.
4. Validasi clientState pada notifikasi, masukkan pekerjaan ke queue, deduplikasi, lalu ambil state terbaru melalui API. Tangani resource yang sudah dihapus dan kegagalan fetch.
5. Uji notifikasi duplikat, renew gagal dan recovery setelah downtime dengan simulasi. Periksa batas resource/jenis perubahan pada sumber resmi.
6. Untuk setup company lewat Automation API, buat rencana izin, review target dan rollback terpisah. Latihan ini tidak membuat company, menginstal extension atau menjalankan webhook publik.

```json
{
  "notificationUrl": "https://<HOST_MILIK_SENDIRI>/bc-notifications",
  "resource": "/api/v2.0/companies(<COMPANY_ID>)/customers",
  "clientState": "<NILAI_RAHASIA_LOKAL>"
}
```

## Contoh praktik

- **Kondisi awal** — Mock mengirim notifikasi perubahan customer yang sama dua kali.
- **Langkah** — Berikan kedua pesan pada simulasi queue dan lakukan pembacaan state terbaru untuk ID tersebut.
- **Hasil yang diharapkan** — Duplikasi tidak menghasilkan dua tindakan bisnis dan kasus notifikasi hilang punya langkah rekonsiliasi.

## Cheat box

<CheatBox>

<CheatGroup label="Notifikasi dan validasi">

- **Notification** bukan hasil posting.
- Validasi **handshake** dan clientState.

</CheatGroup>

<CheatGroup label="Langganan dan duplikasi">

- Catat **expiration** dan renew.
- Antisipasi **duplikasi**.

</CheatGroup>

<CheatGroup label="Rekonsiliasi dan scope">

- Rekonsiliasi berkala.
- **Automation** mempunyai scope berbeda.

</CheatGroup>

</CheatBox>

## Kesalahan umum

:::danger[Kesalahan umum]
Mengabaikan expiry subscription, mengeksekusi transaksi hanya dari payload notification, atau memakai izin automation untuk semua integrasi bisnis.
:::
