**Pola pesan berikut adalah ringkasan, bukan kutipan literal.** Teks dan penyebab dapat berbeda menurut bahasa, extension, dan setup. Reproduksi hanya di sandbox CRONUS.

| Pola / gejala | Cek awal dan tempat menindaklanjuti |
| --- | --- |
| Posting Date tidak diizinkan | Tanggal dokumen; Allow Posting From/To di General Ledger Setup, pengecualian User Setup, dan batas template jurnal bila berlaku. |
| Posting group/setup tidak ditemukan | Pasangan group aktual dan akun wajib; General Posting Setup, VAT Posting Setup, atau setup spesifik pada error. |
| Dimension wajib kosong/tidak cocok | Dimensions pada header/baris, Default Dimensions, Value Posting, dan kombinasi dimension. |
| Nomor tidak dapat diberikan | No. Series yang ditetapkan, baris seri yang berlaku pada tanggalnya, dan Ending No.; jangan reset Last No. Used sembarangan. |
| Tidak punya permission | User/permission set dan objek yang ditolak; minta admin menilai akses minimum. |
| Periode inventory tertutup | Inventory Periods dan pembatasan cost posting; eskalasi ke penanggung jawab closing. |
| HTTP 401 | Cek token/OAuth, masa berlaku, audience, serta permission atau akses company pada BC. Jangan log token. |
| HTTP 403 | Evaluasi otorisasi, akses environment, dan permission aplikasi BC; jangan langsung memberi akses penuh. |

**Saat eskalasi:** simpan pesan asli, langkah reproduksi, jenis dokumen, dan correlation ID bila tersedia; bersihkan data pribadi serta kredensial sebelum berbagi. Bedakan financial posting date restriction dari inventory period; jangan membuka kembali periode tanpa persetujuan.
